설계 철학 정본 = AgentReview 저장소 `docs/philosophy/`(라벨 [사용자]·[AI·제안]) — 걷기·정리 지시문 맨 위에 그 요약(`aar_core/concept.md`)이 자동으로 들어간다.

## 뼈대
- **Path = 근간(사실).** 원자료 줄마다 층 — 실측(fact: 조작·결과·사진·주소·통신·시작 조건) · 생각(thought: 화면 읽기·판단·정리) · 가공(derive). 고치지도 지우지도 않는다.
  무엇을 실측·저장할지(사진 등)는 고정 정책이 아니라 판단 — 남기지 않은 것도 사실로 남는다. 지난 Path 가 재지 않은 요인은 '모름'.
- **걷기 끝 = 드리밍(자동).** 걷기가 끝나면 서버가 ① 지식 노트·색인 정리 ② 노트 확인(이번 사진과 대조) ③ **상태 공간 정리**를 한다.
  상태 공간 = 관측점(그 걷기의 점 — 사실) 위에 AI 가 쓰는 예측: 요인(기저 — measured|inferred)·상태(일부 요인 값으로 정한 영역)·간선(상태 A 에서 조작 → B)·면(보기 — hierarchy|graph|diff).
  시작은 상태 하나 — 나누는 기준·축을 미리 정하지 않는다. 메뉴 트리·세션 트리·화면 지도는 모두 같은 상태 그래프의 면이다.
- **사람 화면** = 작업 공간(`/agentautoreview/` → static/ws.html): 점 보기·Path 재생·상태 그래프·면·AI 대화 패널. 사용자는 표현만, 엔진(원본 층·지식·주입 맥락)은 소유자만.

## 하지 말 것
- 상태·요인·면을 걷기 없이 손으로 지어내기(`state("apply")` 는 근거 관측점이 있을 때만).
- 예측이 틀렸다고 Path(사실)를 고치기 — 예측을 고친다(다시 정리 · 반례로 wrong).
- 사용자 원칙을 "무조건·전부" 같은 고정 규칙으로 옮기기 — 대개 '판단하고 그 판단을 기록'.
- 데이터가 늘수록 느려지는 방식(전체를 매번 다시 쓰기) — 빠른 길(바뀐 것만)과 전체 길(원본부터 다시) 두 길.
