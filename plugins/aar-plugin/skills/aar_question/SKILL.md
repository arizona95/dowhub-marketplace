# aar_question — 짧게 묻고, 포커스 링크로 보여 준다

도구는 aar-mcp 의 `question` 하나다. 규칙 원문은 서버에 있다 — 여기에 다시 쓰지 않는다.

## 1) 규칙 받기 — 대화에서 처음 한 번
`question("guide")` → `rules`(웹 'AI에게 질문하기' 도우미의 규칙 원문: 대상 어휘 · 등록 경로 먼저 · 질문의 방향·범위·개수 그대로 · `[[step:N]]` 자리표)
와 `read_tools`(읽기 도구와 인자). rules 의 'aar-read 도구' = `question("read", …)`, 'StructuredOutput 으로 낸다' = `question("link", …)`.
같은 대화에서 이미 받았으면 다시 부르지 않는다.

## 2) 제품 정하기
질문에 제품이 없으면 이 대화에서 다루던 제품, 그것도 없으면 `question("read", tool="products", args={})` 로 목록을 보고 질문에 맞는 하나를 고른다.
애매하면(후보 둘 이상) 후보를 보여 주고 묻는다.

## 3) 읽고 답하기
- `question("read", tool=<이름>, args={"product": …, …})` 로 필요한 만큼만(보통 2~6번) 읽는다. 같은 도구·같은 인자를 두 번 부르지 않는다.
- 답은 한국어로 짧게(3~12줄) — **읽은 자료에 있는 것만**. 없거나 확인 못 한 것은 "자료에 없음". 숫자·이름·경로·판정은 도구 결과 그대로.
- 판정(O/X/-/?)을 말하면 근거(보기·출처·Exp/Doc)를 같이 적는다(rules 그대로).

## 4) 포커스 링크 만들기
`question("link", product=…, question=<사용자 질문 그대로>, answer=<답 글 — 단계 자리에 [[step:N]]>, steps=[{target, title, text, do?}])`
- 단계 1~7개. 질문에 해당하는 곳을 비추는 순서로(보통 탭 → 그 안의 대상). target 은 read 결과에 나온 값만.
- 응답의 `dropped` 가 있으면 그 단계는 빠진 것(대상이 지금 데이터에 없음) — 답 글과 어긋나면 고쳐서 다시 link.
- 풀린 단계가 0 이면 링크가 안 만들어진다(BAD_INPUT) — 대상을 탭 하나라도 맞게 고친다.

## 5) 사용자에게 보여 주는 모양
```
<답 글 — [[step:N]] 자리는 "(→ N단계)" 로 바꿔 보여 준다>

🔦 포커스 가이드: <url>
   1. <title> — <url>&step=1
   2. …
```
링크는 로그인 없이 열린다(관리자 전용 값은 원래 안 들어간다). 다음 질문이 오면 2)부터 다시 — 앞 답을 맥락으로 쓰되 새 사실은 다시 읽는다.

## 절대 규칙
- **읽기만** — 트리·판정·연결을 고치지 않는다. 고쳐야 할 게 보이면 답 끝에 한 줄로 알리고 사용자가 시키면 그때 해당 스킬로.
- **날조 금지** — read 에 없는 경로·key·id·판정을 쓰지 않는다. 링크는 `question("link")` 가 준 url 만 준다(주소를 손으로 만들지 않는다).
