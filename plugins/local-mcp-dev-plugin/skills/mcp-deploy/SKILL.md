# 사내 MCP 배포 = CI 자동 검사 + 관리자 승인

스크립트: `"<node>" "${CLAUDE_PLUGIN_ROOT}/scripts/kitdev.mjs"`
(치환되지 않았으면 이 스킬의 Base directory 기준 `../../scripts/kitdev.mjs`)

실행기 `<node>`: 이 세션에서 처음 한 번 아래를 실행하고, 마지막 줄 `KITDEV-NODE:` 뒤의 경로를 쓴다.
- 윈도우: `powershell -NoProfile -ExecutionPolicy Bypass -File "<플러그인 폴더>/scripts/node.ps1"`
- 리눅스: `sh "<플러그인 폴더>/scripts/node.sh"`
- PC 에 Node 가 없으면 사내 키트에서 휴대용 Node 를 받아 쓴다(설치·관리자 권한·재시작 없음). 사용자에게 Node 를 설치하라고 하지 않는다.
- 개발자 PC 는 윈도우 11 과 리눅스를 지원한다. 리눅스는 관리자가 처음 한 번 샌드박스 준비(bubblewrap·slirp4netns·AppArmor 프로필)를 해 둬야 한다 — 없으면 setup 이 그 명령을 알려 주고 멈춘다. 그 줄을 사용자에게 그대로 전하고, 내가 sudo 로 대신 하지 않는다.

## 배포 요청
1. 이미 배포(승인)된 적이 있는 MCP 를 고쳐 다시 내는 것이면 `pyproject.toml` 의 `version` 을 올린다(예: 0.1.0 → 0.1.1). 같은 버전으로 내용이 바뀌면 관리자 승인이 거절된다 — 회사 PC 가 같은 버전의 옛 빌드를 계속 쓰기 때문이다.
2. 올리지 않은 변경이 있으면 먼저 `mcp-run` 스킬의 CI 단계(`ci`)로 통과시킨다.
3. 요청을 낸다.
   ```
   "<node>" "<스크립트>" deploy
   ```
   - 키트가 그 커밋의 CI 통과를 다시 확인한다. 통과하지 않은 커밋은 거부된다.
   - 그다음 중앙 검사를 돌린다 — 기본 감사자(SkillSpector·의존성·격리 실행·HITL 및 킬 스위치) + 관리자가 등록한 감사자, 그 결과를 운영자가 보고 승인한다.
4. 요청 번호와 화면 주소를 사용자에게 알린다.

## 상태 보기
```
"<node>" "<스크립트>" status [<요청 번호>]
```
- 반려되거나, 검사 판정이 `차단`(필수 감사자 지적 — 관리자가 승인할 수 없다)이면 걸린 항목(심각도·파일:줄·설명)을 읽고 고친 뒤 버전을 올려 `ci` → `deploy` 로 다시 낸다. 반려를 기다리지 않는다. 검사가 틀렸다고 판단되면 고치지 말고 사용자에게 알린다.
- "배포됐어?"·"승인 났어?" 라고 하면 이 명령을 돌리고 `배포 확인` 줄을 그대로 알린다.
  - `이 PC 의 Claude 에 아직 설치 안 됨` → 출력에 적힌 설치 명령을 실행한 뒤 status 를 다시 돌린다.
  - `회사 Claude 허용 목록에 아직 없음` → 관리자 등록 대기라고 알린다. 내가 설정을 바꾸려 하지 않는다.
  - `배포 완료` → "Claude 를 다시 켜면(/exit 뒤 claude) 쓸 수 있다"고 알린다. 그 뒤로는 이 워크스페이스의 개발본이 아니라 배포본을 쓴다는 것도 말한다.

## 지켜야 할 것
- 승인은 관리자 몫이다. 승인을 재촉하거나 우회하는 방법을 찾지 않는다.
